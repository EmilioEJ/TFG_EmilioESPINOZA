\chapter{Implementación, Pruebas y Resultados}
\label{chap:implementacion}

\section{Descripción de la Solución}
La solución implementada consiste en un prototipo funcional de un Asistente Virtual Inteligente diseñado para la difusión proactiva de reglamentos y mallas curriculares. Para superar las severas limitaciones de latencia y pérdida de contexto asociadas a los modelos de inyección de contexto completo, la solución adopta una arquitectura de Generación Aumentada por Recuperación (RAG). 

El sistema está estructurado en tres capas operativas distintas que funcionan sobre un modelo de computación de borde (\textit{Edge Computing}):
\begin{itemize}
    \item \textbf{Capa de Percepción:} Un módulo de visión artificial en el cliente que detecta la presencia del usuario sin comprometer la privacidad.
    \item \textbf{Capa Cognitiva (Motor Principal):} Un entorno local administrado por FastAPI, donde interactúan una base de datos vectorial (ChromaDB), un sistema avanzado de transcripción de voz (Whisper-v3) y un modelo de lenguaje de ejecución local (Qwen 2.5).
    \item \textbf{Capa de Interacción Frontal:} Una interfaz basada en web que renderiza un avatar 3D mediante WebGL, permitiendo interacciones sin el uso de periféricos tradicionales (manos libres).
\end{itemize}

\section{Proceso de Implementación}
El proceso de implementación se ejecutó garantizando el aislamiento de procesos y priorizando la reducción de latencia en cada componente lógico.

\subsection{Implementación de Visión Artificial Ligera}
Para detectar a los usuarios de manera proactiva sin incurrir en altos costos computacionales, se implementó un algoritmo ligero utilizando OpenCV y clasificadores optimizados (como MediaPipe). El sistema extrae un único fotograma de video cada 500 milisegundos. En lugar de ejecutar redes neuronales convolucionales profundas para reconocimiento facial, el módulo se limita a detectar la caja delimitadora (\textit{bounding box}) del rostro.

\begin{equation}
\label{eq:presence}
Estado = 
\begin{cases} 
Activo, & \text{si } (W_{box} \times H_{box}) > \tau_{pixeles} \\
Reposo, & \text{de lo contrario}
\end{cases}
\end{equation}
\addeqtolist{Cálculo lógico para detección de presencia del usuario}

Si el área supera el umbral predefinido (indicando proximidad al kiosco interactivo), se dispara un evento lógico para encender el micrófono. Este enfoque mantiene el uso de CPU por debajo del 5\%.

\subsection{Procesamiento de Documentos y Motor RAG}
Una dificultad constante en la arquitectura RAG es la ingesta de tablas dentro de documentos PDF. Para abordar esto, se utilizó la biblioteca \texttt{pymupdf4llm}, la cual traduce el contenido del PDF directamente a formato Markdown. Las mallas curriculares se convierten en tablas Markdown explícitas (ej. \texttt{| Asignatura | Nivel | Horas |}), conservando así la relación dimensional.

Los documentos son divididos utilizando \texttt{MarkdownTextSplitter} de \textit{LangChain}, con un tamaño de fragmento (\textit{chunk}) de 2500 caracteres, para luego ser transformados en vectores numéricos de 768 dimensiones. Estos vectores se almacenan en \textbf{ChromaDB}. 
Durante una consulta, la similitud entre el vector del usuario ($\vec{q}$) y los documentos ($\vec{d_i}$) se calcula mediante la Similitud del Coseno:

\begin{equation}
\label{eq:cosine}
\text{Similitud}(\vec{q}, \vec{d_i}) = \frac{\vec{q} \cdot \vec{d_i}}{\|\vec{q}\| \|\vec{d_i}\|}
\end{equation}
\addeqtolist{Cálculo de Similitud del Coseno en el motor RAG}

Para corregir problemas semánticos donde los estudiantes utilizan lenguaje coloquial (ej. pedir "semestres" en lugar de "niveles"), se implementó un mecanismo de \textit{Query Expansion} en el backend que enriquece heurísticamente la consulta con sinónimos antes de vectorizarla.

\subsection{Procesamiento de Voz en Backend con Whisper}
Para lograr compatibilidad multiplataforma y evitar los bloqueos de APIs de terceros en los navegadores, la conversión de voz a texto (STT) se desacopló del cliente. El \textit{Frontend} captura paquetes de audio nativos (\texttt{.webm}) usando la API \textit{MediaRecorder} y los transmite a un \textit{endpoint} \texttt{/api/stt} en FastAPI. El servidor luego delega la transcripción al modelo \textbf{Whisper-v3} de OpenAI a través de la API ultrarrápida de Groq. Esto asegura transcripciones instantáneas y alta precisión en el idioma español.

\subsection{Interfaz y Avatar 3D}
La interacción final fue desarrollada utilizando \textit{Three.js} para renderizar un avatar de formato VRM directamente en el navegador (WebGL). Se programaron dos modos visuales (Dual UI Mode): un modo "Chat" tradicional y un modo "Conversacional" inmersivo sin texto en pantalla, enfocado en el uso exclusivo de la voz. El modelo aplica interpolación de funciones matemáticas para sincronización labial (\textit{lip-sync}) y realiza simulaciones de respiración y contacto visual interactivo.

\section{Pruebas y Validación}
La validación del sistema se enfocó en medir la optimización del tiempo de respuesta y la precisión en la recuperación de los documentos. Las pruebas se ejecutaron en un servidor local estándar simulando el entorno de un kiosco interactivo universitario (CPU de 8 núcleos, 32 GB de RAM, GPU dedicada de 8 GB VRAM). 

Se construyó un \textit{Dataset} de validación con 100 consultas estándar de estudiantes para evaluar el motor semántico utilizando la métrica de Rango Recíproco Medio (MRR) y el \textit{Hit Rate} para los 3 documentos más relevantes (Top-3). Asimismo, se realizaron pruebas de estrés para medir el consumo de memoria unificada.

\section{Resultados}

\subsection{Reducción de Latencia}
Se comparó la arquitectura implementada (RAG) contra un enfoque anterior de "Inyección de Contexto Completo" donde un documento PDF de 40 páginas se introducía completo en el modelo para cada consulta. El uso de RAG y ChromaDB redujo drásticamente el "Tiempo hasta el primer token" (TTFT). Como se observa en la métrica, para consultas simples de prerrequisitos, el tiempo de respuesta cayó de 8,5 segundos a 3,2 segundos (una reducción del 62\%), permitiendo un diálogo fluido humano-computadora.
